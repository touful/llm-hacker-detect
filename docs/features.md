# 特征口径：passive-http-v1

接收数据时没有原前期实现、完整列名字典或其 OOF；本仓库已生成自己的实现和折外预测。维数和题给定的模型结构按规格实现；以下是可复现的工程定义，不声称与历史向量逐列兼容。源码：capture.py（记录解码）、features.py（白名单）、views.py（组合）。所有切片为从 0 起的半开区间。

**Conv-All。** 通用四统计依次是均值、总体标准差、中位数、最大；无法计算为 NaN。

- [0,24)：观察时长、段数、包数、字节数；对段包数、段时长、段间空闲、相邻段包数绝对变化、相邻段时长绝对变化各取四统计。间隔 >1 s 开新段。
- [24,43)：前 128 个支持的传输层包（或到场末）的正方向比例、方向切换率、包长四统计、窗口内开始的请求/响应数、GET/POST/HEAD 比例、路径深度均值与 SD、带查询比例、字段数与去重字段数均值、相邻请求的顺序结构/方法/路径深度切换率。这是离线签名；头部按起始时间归属窗口。
- [43,71)：流数、双向与短流（≤4 包）占比、生命周期与流包数各四统计、最大流字节与包数占比、正方向比例、按时间相邻包的方向切换率、闭区间流并发峰值、三个等时阶段的包数份额/字节份额/正方向比例、全场平均包长、请求中浏览器/脚本占比。
- [71,145)：21 个阶段风格值、五种状态族（1xx 至 5xx）各十项转移比例、三个阶段漂移。对同流每个响应时刻前后毗邻的两个请求比较：方法改变、后为 GET、后为 POST、查询项数改变/增加、深度改变/增加、字段顺序改变、字段集合改变、粗客户端改变。不等价于推断因果响应匹配。

**请求与风格。** 按 floor(16 × 从零开始的请求序号 / 请求数) 入箱；11 类为 host/user-agent/accept/accept-encoding/accept-language/connection/content-type/content-length/cookie/referer/other。前十类构成 10×9 个有向先后对，同字段首现决定先后。占比的分母是箱内所有请求，包括没有这两个字段的请求。第 102 列为相邻结构切换率（只一个请求时未定义），第 103 列为不同结构数/请求数。空箱为 NaN。风格按抓包观察时段（三等分）而非请求序号分割：每段 UA/Accept/Accept-Language/Accept-Encoding/Cookie/Referer 出现比例及 Host 居首比例。两两跨段 7 项绝对差的均值，缺阶段不补零。

**Dist24 列顺序。** [0,1648) 原始箱行优先；[1648,2060) 按列取有效箱最小、最大、按请求数加权均值、加权总体 SD；[2060,2150) 90 个顺序对是否出现；[2150,2166) 每箱与加权均值的逐有效维平均绝对偏差；[2166,2190) 时间风格 24 维。全场无请求则整个向量为 NaN，而不是“每个顺序都未出现”。

**观察边界。** 读取经典 PCAP（以太网、Linux cooked v1/v2），含 VLAN，支持 IPv4 与无扩展头 IPv6 的 TCP/UDP。跳过 IP 分片及不支持的传输协议；包数因此可能小于原始记录数。每条流正方向指首次出现的一侧，不保证是选手。未做目标侧地址白名单；研究结论是当前抓包范围内归因。地址、端口、绝对时间、请求值/路径、原始 UA 和报文正文均不作为模型列或持久输出。

HTTP/1 解析按每个方向的连续 TCP 序号接收、去除重传重叠、拼接完整首部、按 Content-Length 跳过消息正文；不猜测丢包或乱序后的消息边界。chunked、upgrade、close-delimited 响应会停止该方向后续首部解码；不处理加密流量、HTTP/2、隧道和复杂响应语义（例如 HEAD 的 Content-Length）。因此“不限包”意指读到文件末尾，不意味着恢复了全部应用请求。未知字段归为 other；路径深度为原始 target 按 / 分割后的非空项数，不解码转义；查询数同理按 &。客户端三分类仅为 UA 粗分类，不作为人类/Agent 真值。读取逐记录进行，每次只保留一个 PCAP 的事件列表；**整场特征内存随包数增长**，超大抓包宜预留主存或明确采用统一包预算，不静默截断。
